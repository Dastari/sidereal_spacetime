# Static delivery and dynamic state: measured follow-up

Read-only audit on2026-09-10, after the refit authority gates and before the loading-screen release. This does not change the deployment candidate. HTTP measurements used the actual public2f5c release from the local network; response durations are not internet/user benchmarks. Source measurements use current runtime artifacts and installed SDK code.

## Findings

| Measurement | Result | Meaning |
| --- | --- | --- |
| Public entry JavaScript GET with `Accept-Encoding: br, gzip` |789,532 original bytes;221,242 gzip response bytes | JavaScript compression already works. HEAD did not report that encoding, so HEAD alone was misleading. |
| Public assembly catalog GET |256,362 original bytes;21,474 gzip response bytes | JSON compression already works. |
| Public modular crew GLB GET |14,775,768 response bytes; no content encoding | Native binary geometry is presently transferred uncompressed (`model/gltf-binary`). |
| Offline gzip6 of the exact same crew bytes |1,534,064 bytes | Approximately90% smaller transfer is available without altering any authored mesh or the decoded asset hash. This is a compression-size experiment, not deployed evidence. |
| Offline gzip6 of parts.glb |23,903,376→3,711,217 bytes | Approximately84% reduction; likewise no geometry simplification required. |
| Local native library versus remote exterior library |13 common URLs,8,994,484 source bytes | These loaders have independent fetch/hash/import maps. Browser cache may avoid repeated wire bodies, but separate import/parse/GPU work remains. This is source overlap, not a measured duplicate-download count. |
| Runtime files |1,239 files;355,514,617 logical bytes; approximately204MiB allocated | GLB207,966,380 bytes and PNG125,950,686 bytes dominate. ZFS compression explains logical versus allocated differences. |
| Byte-identical runtime copies under different paths |18 duplicate groups;25,684,288 excess logical bytes | Potential delivery/catalog deduplication; do not delete proof-qualified aliases blindly. |
| Client public/dist + dashboard public/dist |361,346,107 /366,881,814 /361,346,954 /367,084,990 logical bytes | Preparation copies the complete runtime tree into both independent apps and Vite copies public into each dist. Those are filesystem copies, not evidence a browser requests every file. |
| Retained public releases |12 directories;4,288,152,085 logical bytes, approximately2.5GiB allocated | Repeated complete asset trees provide rollback history. Preserve that history while improving future storage. |
| One current public native instance |70,555-byte document JSON plus21,875-byte server ID map | The owner view sends the document; the ID map is server-only. The document is immutable and separately keyed from motion. It is not shown to rewrite every simulation tick. |

Storage accounting also distinguishes durable recovery from disposable asset copies: the live standalone currently occupies approximately16GiB, while the four retained credential-bearing recovery archives allocate approximately12+13+15+15GiB. Those verified recovery histories dominate the current disk usage, not the2.5GiB of public release copies. Retention/off-host replication should be planned separately; this audit authorizes no deletion of unique recovery history or isolated proof databases. CT107's bounded quota increase provides space for the next fresh backup without such deletion.

All tested static routes currently respond `Cache-Control: no-cache` with validators. This means revalidation, not necessarily redownloading every body. The public Vite preview and NPM configuration currently disable proxy caching. Hash-named JavaScript could safely receive immutable caching; stable names such as parts.glb and catalog.json cannot safely receive year-long immutable caching while their bytes can change at the same URL.

The installed SpacetimeDB2.10 SDK already defaults to gzip. Its `withCompression('brotli')` explicitly requires browser `DecompressionStream('brotli')` support and throws when unavailable. Blindly switching it would introduce a login failure on unsupported browsers. `withLightMode` exists, but reducer/error confirmation behavior must be tested before changing transport semantics.

## Recommended order after the construction release

1. **Compress native binary delivery without changing decoded bytes.** Add precompressed gzip/Brotli artifacts or narrowly configured gzip for the actual GLB MIME type at the managed static server/proxy. Preserve exact decoded hashes and MIME types; negotiate encoding and `Vary: Accept-Encoding`, test ordinary and conditional GET, cache variants and range behavior. The two measured GLBs alone shrink from38.68MB to5.25MB at gzip6. Verify actual browser transferred sizes, not only local compression output. JavaScript/JSON already compress; do not claim those savings again.
2. **Share verified asset bytes and bound loading concurrency.** Introduce a URL+SHA keyed promise/cache shared by the local native and remote-exterior loaders. Share decoded prototypes only within one Babylon scene, retaining independent placed UUIDs, skeletons/state, reference-counted disposal and GPU ownership. Fetch/hash a bounded number of independent files concurrently; preserve failure/retry and loading progress. Never let an old scene's disposal delete the replacement scene's resources.
3. **Make immutable URLs explicit, then cache them.** Content-address runtime assets or version the whole immutable asset namespace. Keep small live entry/config/manifest documents revalidated. Maintain the existing exact source pin checks through this migration, including installed manifests and qualified geometry evidence. Do not slap immutable headers on today's mutable filenames.
4. **Reduce build duplication separately from network traffic.** Use an explicit app-specific runtime dependency manifest and atomic preparation, rather than copying the entire runtime tree with `dirs_exist_ok=True`, which can also retain removed files. Preserve dashboard/client build boundaries. For future releases, use a verified immutable content store with safe hardlinks/reflinks or equivalent manifests; never mutate a shared inode and never delete rollback assets still referenced by retained releases.
5. **Measure dynamic traffic before schema surgery.** Capture cold admission,60-second idle, walking, flight, two-account proximity change and token replacement. Record WebSocket bytes/message counts, actual row sizes and per-table events. Keep current private authority, accepted discovery, keyed views and change-only motion. The current70.6KB immutable instance document is a candidate for revision/hash-addressed caching and lean admission metadata, but arbitrary private player-authored designs must not become publicly accessible just to save traffic. Brotli should be feature-detected with gzip fallback; light mode requires explicit reducer/error/replay tests.

Keep geometry simplification, KTX2/mesh compression and material changes as later separately validated work. The first delivery pass can preserve every approved Blender surface, collision proof, asset hash after decompression and gameplay identity.
