## Reproduction phases

Use the Playwright skill wrapper and named session `native-pressure-review`, with `/tmp/sidereal-light-browser.json`. No browser is opened by the preparation command.

1. `setup.js` installs browser-local database routing for the normal game and authoring transports, approved game review-origin configuration and observation hooks. It opens the real Shipyard app at `https://sidereal.tail7a58a6.ts.net:8445/shipyard`. Only authority websocket connections are retained, preventing concurrent Vite HMR from replacing the candidate mid-review. RAF is paused for controlled complete-frame rendering on SwiftShader.
2. Sign in through the existing provider UI after root grants the role. `.runtime/native-pressure-review/signin.py authoring` submits the existing `/tmp/sidereal-auth-review.json` credentials without printing them; its raw CLI echo is restricted to a private `/tmp` log. The helper assumes the actual login form is already open.
3. `publish-spawn.js` grants four scoped one-hour capabilities using the provider-admin authority, saves the exact native document, publishes through the normal reducer, and spawns two fixed room instances. It validates different placed deck/door identities and refuses to duplicate an existing workspace installation. Record returned blueprint hash and instance IDs.
4. `game.js` opens the real game candidate at `https://sidereal.tail7a58a6.ts.net:8444/?constructionReview=1`; sign in normally, using the same private account and the `game` helper mode when needed. Game subscriptions must include the generated `ownConstructionNativePressure` projection before this phase.
5. Use the actual walking-review buttons to enter each room, keyboard motion to test closed/open doorway collision, door controls to capture ordered seal retraction/hinge motion/reseating, and complete rendered frames to verify native gasket geometry. Preserve the standard original-ship return state, inventory and appearance. Never inject gas or set arbitrary actor positions.
6. `pressure-snapshot.js` reads native pressure, ordinary doors, visit and character coordinates. It rejects any nonzero pressure or vented gas in the vacuum fixture. Capture both instance states independently; the untouched sibling must retain its door/seal state. Actual gas transfer is not exercised by vacuum rooms; nonzero-flow claims remain adapter-test evidence only.
7. Reconnect the owner with the ordinary page reload and compare accepted door/seal state, visit identity, position and pressure rows. `privacy.js` additionally subscribes as a separate ungranted principal, reconnects that same principal using its in-memory token and verifies empty pressure/instance/door views both times. It creates no character or items and never exports its token.
8. Return to the original ship, restore controls, capture fixture preservation, sign out and close the named browser. Root revokes the temporary provider role. Record actual outcomes and limitations here only after those steps complete.

All browser evidence belongs under `output/playwright/native-pressure-room/`. SwiftShader frame counts and screenshots validate behavior, not hardware FPS. Existing native source files and the normal world module remain untouched.
