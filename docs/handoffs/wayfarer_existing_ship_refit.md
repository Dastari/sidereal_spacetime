## Atomic conversion adapter requirements

1. An explicit refit request supplies an operation ID and expected current ship/inventory/instance revisions. Reread the actual actor, ship, station, control/input lease, complete inventory and installed interaction graph. A repeated operation returns the recorded result without allocation or revision churn.
2. Preserve the current ship world pose, velocity, heading and accepted shared admission. Do not reserve a new berth. A private legacy actor first needs its separate explicit Join shared system action; that relocation must not be disguised as refit or happen at login.
3. Require a supported current standing pose and an empty station with no live pilot input. Historical actor positions may overlap the new native seat; have the player walk to a valid location beforehand instead of teleporting. Preserve the station UUID while validating its native source/socket and operational state; an owner relation grants no pilot control.
4. Preflight all structural source aliases, cargo bindings, nested inventory scopes, existing sofa/light identities and state, and flight fitting/source-device aliases. Legacy actuator IDs are per-ship content identifiers; record their mapping explicitly rather than claiming they were global fitting UUIDs.
5. In one reducer transaction install the exact qualified instance with the existing ship UUID, preserve the original station and interaction UUIDs, bind all existing grid/liquid roots and update every affected scope/membership. Preserve grid coordinates, rotations, nested items, hotbar, equipped items, weapon energy, appearance, uniform-issue records and liquid balances. Never call the fresh-only cargo/flight writers on existing rows.
6. Create a conversion receipt and durable game-owned access relation, separate from starter entitlement and all authoring grants. Extend the kit guard to recognize converted access: the existing guard recognizes only a personal starter receipt, so a converted legacy account must not fall through to laboratory root recreation. Existing native reconnect should remain connected-state-only. Preserve the review-return behavior for genuinely temporary granted visits.
7. Prove preflight rejection and late-write rollback, then perform an isolated pre-upgrade legacy fixture conversion with exact hidden-item/container/appearance comparison, replay, reconnect, actual process restart, cargo/liquid operation, walking/collision, pilot controls and cross-owner denial. Public conversion follows only that matched client/module evidence.

## Registered conversion checkpoint (supersedes preflight-only runtime status)

The working module now registers `wayfarerRefitReceipt`, `wayfarerRefitAttachment` and `wayfarerLiquidReceipt` privately. `wayfarer-refit-authority.ts` implements the actual typed database transaction; `wayfarer-refit.ts` reuses exact source qualification with the existing ship and station UUIDs. The existing actor row, world admission and world motion are not rewritten. Only the ship's revision advances. A changed legacy flight rating rejects conversion rather than silently resetting it to current starter ratings.

The request has ship ID, expected ship/inventory revisions, a server-offered full-state fingerprint and operation ID. The fingerprint includes current inventory payload, capacities/balances, station and interaction state; those rows are reread before writes. An occupied station, seat, nonzero movement input, active construction review origin, missing explicit shared admission, corrupt inventory or unsupported current standing pose rejects conversion. A quiescent input lease is retained, not treated as pilot authority. The same successful request replays without allocation; a different request against an already-converted ship rejects.

The adapter preflights all cargo access points and pilot geometry, then installs structural mappings, keeps each old station/container/item/interaction UUID, backfills historical inventory sidecars, changes installed-root scope and nested membership atomically, preserves light enabled/revision values and retains existing uniform-issue/hotbar/appearance records. It creates no cargo contents, authoring grants or personal starter entitlement. Existing nonfunctional visual crates remain unbound when an old ship had fewer roots. `preserveWayfarerStarterKit` now recognizes verified durable converted access even without a starter receipt, preventing laboratory storage from being issued again.

The fuel attachment is qualified independently by `PRESERVED_FUEL_MOUNT` and `requireQualifiedPreservedFuelMount` in `wayfarer-refit-mount.ts`. Runtime reads the vendored native certificate, revalidates the supported layout/approach and requires the exact source/asset hashes, position and original100L/80kg limits. It is an explicit provisional nonstacking floor mount, not a filled-stacking or mesh-derived load claim. Conversion and every collision lookup consume this predicate. `constructionCollision` adds its conservative1×1m obstacle without changing the canonical base document or bypassing roof/source validation.

`transferWayfarerLiquid` supports an explicit manual transfer between this mounted fuel root and a currently carried canister reservoir. It requires live gameplay admission, the current supported owned visit, clear reach to the tank, compatible fuel, finite bounded litres, source/destination/container/inventory CAS revisions, liquid capacity, reservoir mass and full carried-inventory mass validation. Both balances and all relevant inventory revisions update in one transaction; replay still rechecks access. This is not automatic piping or systems flow. Solid-item cargo transfer continues rejecting liquid containers.

The generated client contracts are `ownWayfarerRefitOffer`, `ownWayfarerRefitAttachments`, `refitExistingWayfarer` and `transferWayfarerLiquid`. Both views have primary keys and use the normal authenticated game gate. The attachment view additionally requires current game-owned interior access and supplies only the accepted instance/deck/object/container IDs, fixed native asset/hash and pose. Root owns the explicit normal-game refit action, appended native visual/inspection and liquid panel.
