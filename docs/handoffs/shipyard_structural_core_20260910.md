# Shipyard structural authoring core

2026-09-10 implementation of the [owner's nine rules](shipyard_owner_rules_20260910.md), restricted to authoring intent and deterministic validation. No world module, generated bindings, native assets or live instance was changed by this slice.

`LayoutDocument.structure` is optional and versioned `sidereal.layout-structure.v1`. Absent fields preserve the existing compiler path and the exact canonical Wayfarer source SHA `362f37217f63a44a470676f104c8368bd0973ca03f5e29eab190bc4d6df71340`. Explicitly selecting a hull creates a new authored document; it is not a migration of an existing live source.

- `HullEnvelope` snapshots an editable catalogue entry: ID, revision, name, width/X, length/Y, height/Z and minimum XYZ origin, all integer 1/32m units. Every deck ceiling/floor interval and every floor polygon must fit. Reserved deck height intervals cannot overlap. The initial catalogue contains the existing Wayfarer's usable 10×22m footprint and a 3m height; these are editable authoring bounds, not balanced hull classes.
- The 2m module is64 units. Internal wall nodes use explicit16/32/64-unit subdivisions. Cardinal walls require continuous floor on both sides; diagonals follow actual shared polygon interfaces. Boundary-coincident editable walls, overlapping partitions and off-lattice crossings are rejected. The compiler derives immutable perimeter walls from each deck's floor union, including void boundaries.
- `CompiledLayout.structure` exposes directed spans and generated end/straight/corner/T/cross/multi junctions, incident wall IDs and exterior tie-ins. `deletable:false` identifies generated perimeter spans. Wall finishes use separate `left`/`right` values relative to the source a→b direction. Topological meeting points are exact; native junction/panel adapters remain `null`, not implicitly qualified.
- Openings retain their stable identity and `partitionId`; external apertures reference the existing generated perimeter `anchorId`. `wallOpeningSlots` supplies floor-edge midpoint slots and whole2m cardinal slots along subdivided internal walls. Width is an integer dominant-axis span; diagonal physical width is the Euclidean endpoint distance exposed in the compiled opening. Diagonal requests producing fractional lattice endpoints reject. A wide external aperture can span straight tile seams, but jamb reservations cannot reach a corner, T/cross node or wall end. Overlapping openings/jamb reserves, structural/fitting sweep intersections and unsupported internal approaches reject. `setback` defaults to4 units (0.125m), an explicit draft reservation needing actual native frame qualification.
- Exterior opening intent permits the empty outside side but always reports missing landing/boarding/native-interface qualification. Door/airlock intent is distinguished from open passage intent; no room name creates a seal and this does not install door operation, interlocks, gas, power or a traversable external landing.
- Floor styles stay keyed to semantic tile IDs, not fitting placements. Material overrides appear in compiled tiles. Exact model ID/revision selections now require a matching entry in the pinned r002 nominal floor kit, including polygon, deck datum and permitted transform. The shared binder uses this selection, so the existing native renderer follows it without creating an ordinary fitting. Unknown or differently shaped selections reject; future kits require separate qualification. Missing tile/finish/boundary anchors reject rather than silently losing a saved choice.
- Armor reservations must be convex, contact their selected perimeter, remain outside usable floor area and fit the declared deck height. This is nominal reservation validation. Actual structural wall thickness, armor sockets and complete exported native geometry still need their independent catalogue interfaces; no strength or penetrability is inferred.

The exported editing helpers `setHullEnvelope`, `setWallFace`, `setFloorStyle` and `proposeWallOpening` clone the document, compile the complete candidate and throw before returning on any error. The editor applies the returned document as one undoable edit. It must deliberately reconcile stale finish/model/armor anchors when deleting floor areas, preserving recovery bytes. Directly deleting a derived span or adding a floor through a generic fitting list is not an operation in this contract.

Subgrid wall geometry is supported, but existing named-room grouping still follows whole floor tiles. A diagnostic identifies that limitation; it is not a finite gas-volume proof. General generated native junctions, panel finishes, door models/sweeps, sealing and functional boarding require further integration. Existing native qualification and exact-source authority guards remain in force.

Validation:49 focused tests passed across the new structural contract, legacy layout compiler, construction transactions and topology. This includes all three envelope axes, per-deck regeneration, exact old-source hash, independent faces, T/cross ties, atomic failures, diagonal rotation/reflection cases, wide exterior openings, sweep/jamb exclusions, model/style references, armor rejection and deterministic graph output. New-file ESLint passed. Combined dashboard typecheck/build/browser acceptance remains the parent integration gate; no public release is claimed here.

## Native floor override follow-up

`floorModelOptions(tile, elevation)` and `matchNativeFloorTile(tile, elevation, model?)` are exported from `@sidereal/sim/layout-native-floor`. Options expose the exact asset ID, native revision, SHA, node selector and stable tile placement. No arbitrary visual catalogue asset can establish its own support interface. Absent overrides preserve the prior first-approved-match behavior; forbidden reflection is never inferred from geometric symmetry. The binder emits unmatched IDs for unavailable overrides, and direct construction compilation rejects a supplied floor binding that differs from its selected native model. Model choice does not recolor native material maps or invent an alternate variant where only one matching native shape exists.

`assertHullEnvelopeFits(doc)` is a narrow immediate edit guard for W/L/height only. It does not reject unrelated stale styles or room diagnostics, allowing recoverable drafts to continue being edited. Full publication still uses the complete compiler.

Full project typecheck passed. Renderer catalogue matching must retain SHA, node prefix and native revision checks; the game loader already checks all three.
