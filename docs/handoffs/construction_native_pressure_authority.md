# Bounded native room pressure authority

2026-09-09. This adapter applies only to the exact R006/a007 native pressure room. It is an intermediate construction slice, not a full Wayfarer pressure system or powered external airlock.

`packages/world/src/construction-native-pressure.ts` binds the server instance document, authoritative door frame, exhaustive placed-part list and native audit SHA to a private installation. `acceptNativePressureRoomInstallation` checks every identity, source SHA, node prefix, origin and quarter turn. The compact published compiler validates its exact audit bytes; publication independently checks the native GLB dependencies. Generic `validated: true` objects and client volumes are not reducer inputs.

The private `constructionNativePressure` table stores accepted hinge and gasket state plus installation provenance. The existing private `constructionDoor` hinge remains the collision state. Generic door stepping explicitly skips this fixture. Its native controller retracts the gasket before moving the hinge, closes the hinge before deploying the gasket, and conservatively refuses either movement while a character intersects the reserved source sweep envelope. Any positive gasket retraction restores the named finite review flow. Zero flow requires the exact qualified native installation with both accepted fractions zero. The review actuator is explicit always-available development policy; power supply, pressure-differential interlocks, emergency overrides and external airlock cycling remain unimplemented.

Global admission permits at most 32 pressure installations, aligned with the finite solver budget. The 33rd installation rejects before pressure writes inside the spawn transaction; exact retries remain valid at capacity. Settled-room ticks reuse only derived validation/topology cached by exact persisted bytes and accepted pose. Same-revision source, document or model edits still invalidate/reject; gas and clocks are never cached as authority.

The private `constructionAtmosphereClock` persists one 50 ms simulation count per increasing scheduler timestamp. Duplicate or older scheduling timestamps do nothing. A long downtime still produces only one fixed step when scheduling resumes. Neither connection hooks nor installation retry initialize gas again. `constructionAtmosphere` stores finite gas, source allocation accounting, vent/capture counters and revisions. Persistent accounting rejects nonfinite or unexplained quantities before stepping.

Installation starts in vacuum. This adapter exposes no gas charge reducer and creates no review gas resource. Nonzero tests explicitly inject a finite, source-accounted test setup; that is test code, not a production allocation interface. A future charged template must debit a defined resource/allocation in the spawn transaction. Current code does not claim that resource path exists.

The narrow native pressure view requires an owned current instance plus an unrevoked readable workspace grant, under the normal game admission wrapper. It exposes compartment pressure/volume and accepted door state, not private source/model rows. Door commands require a connected character in the owned instance, matching visit/deck, reach, current spawn grant, expected door revision and operation receipt. Grant checks occur before replay acceptance.

Targeted unit coverage includes exhaustive installation tampering, invalid frame/owner, vacuum default, finite conservation, gasket/hinge sequence, obstruction during initial retraction and final deployment, generic hinge bypass rejection, immutable document binding, independent instances, duplicate ticks, serialized restart without catch-up or refill, private view access, stale requests and revoked/disconnected replay rejection. This record is not actual database restart or browser evidence; aggregate builds and isolated database/browser results are recorded by the integrating root task.

Required integration hooks: register all three private tables, call `installNativePressure` in validated native spawn after native placement/door creation, call `stepNativePressure` from the server-only world scheduler, register `ownNativePressure` through the admitted game view, and generate bindings. Renderer placement and native static collision must consume the same exact published fixture. Any refit, extra equipment, damage or changed structural layout needs a separately validated replacement; it cannot retain this fixed room qualification.
