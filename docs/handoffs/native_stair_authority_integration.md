It persists XYZ separately while ordinary character XY/source deck remain unchanged until the terminal landing commit. ## Accepted conservative recovery policy

- Lost/stale input or disconnected actor: return **only the incomplete current riser** along its qualified physical lift/advance/settle path; stop on the last supported stance and retain reservation. Never auto-return the entire flight or teleport through the stair.
- Workspace grant loss: the first detected edge interrupts an incomplete riser the same way and latches `egressOnly`. A still game-admitted, connected, input-authorized owner can then drive that same active stair occupancy toward either genuine landing, through only the previously committed proof. No new entry, seat/combat/inventory operation or general workspace access is granted. On landing, invoke the safe access-loss exit hook; no reentry is allowed without a newly valid grant.
- Lost game admission or movement lease: no driving even with workspace permission or egressOnly. A disconnected actor remains supported. Reconnection must recover normal auth/input authority before driving resumes.
- Geometry/identity/reservation mismatch: hold accepted pose and reservation, exposing a blocked own status. No guessing a new support. Repeated identical validation faults do not rewrite the same row. Root must prevent such invalidating edits through ordinary authority; exceptional repair remains a separately validated operation, not automatic relocation.

Validation errors are evaluated before normal commit and can hold an individual malformed stair without preventing others progressing. Storage or terminal-hook errors deliberately propagate for whole-transaction rollback. JavaScript try/catch cannot make arbitrary partial reducer writes safe, and this adapter does not claim otherwise.

Remaining limits: fixed reviewed fixture, one passage occupant, only the current standing body, no elevator or arbitrary stair placement, no live rendering acceptance, and no pressurization/destructibility rating inferred from visual stairs. Terminal audits currently use bounded admission rather than automatic historical deletion; owner cleanup/export policy is separate.

### Actual safe review exit semantics

`completeSafeEgress(characterId, walkId)` requires a matching freshly committed `egress-exited` stair audit, current visit/deck/actor, no remaining active stair row, active game admission and an owned usable input lease. It then calls the existing `construction-instances.leaveReview` directly with:

- `sender` set to the verified actor owner for this internal scheduled operation;
- `expectedVisitId` and `expectedRevision` taken from the just-committed current location row;
- deterministic `operationId = "stair-egress:" + walkId`.

The existing `leaveReview` checks connected character, ladder standing guard, exact visit/revision, current instance and existence of `returnShipId`; it restores the server-stored `returnX/returnY`, deletes the construction visit, clears controls and records a bounded construction receipt. The helper explicitly rejects a mismatch with that function's current first-owned-character lookup. It does not duplicate return coordinates, invent client transforms, reseed inventory or select another character.

`mayCompleteSafeEgress` preflights stored return ship existence, finite saved coordinates, active admission, expected current actor selection and receipt capacity. If game/input admission is missing, the actor remains **supported with reservation held**, even at a landing. If the return target/receipt capacity is unavailable, the actor remains supported and blocked with `safe-egress-unavailable` until an authoritative repair. These cases do not repeatedly throw and roll back the world tick. Unexpected storage or exit-hook failures still propagate for atomic SpacetimeDB rollback.

This is the existing explicit **development review portal return**, not physical docking, an exterior airlock or an elevator. Existing `leaveReview` does not revalidate the old ship's floor collision at `returnX/returnY`; it only verifies the ship still exists. This adapter preserves that current contract and does not claim a new general safe-teleport capability. A later live refit/destruction path must invalidate or requalify stored review-return anchors before changing their support.
