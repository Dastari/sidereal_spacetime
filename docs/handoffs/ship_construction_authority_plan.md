# Ship construction authority implementation plan

Status: read-only audit and proposed implementation slices, 2026-09-09. No construction schema or live data was changed for this plan. Implementation ownership belongs to `integration_continuation`. [Ship construction rebuild](../ship_construction_rebuild.md) is the completion contract: a playable multi-deck Wayfarer, pressure/airlock, cargo stacking, spatial services and independent template spawns. A single-deck demonstration is an intermediate gate only.

## First implementation slice: published documents and isolated authored instances

Deliver an end-to-end server draft → immutable published revision → independently spawned authored instance, with topology-driven planar walking, alongside the unchanged legacy laboratory frame. Use a two-deck document in the schema/test fixture from the beginning. Both decks compile and retain distinct collision/visual support; the first browser walk on one deck is not the completed multi-deck milestone. A separate second slice enables actual validated transitions.

Initially permit only structural adapters with approved nominal geometry, simple installed fittings and empty storage with explicit development capacities. Reject unresolved functional declarations rather than silently accepting a decorative engine as powered. Publication reports capability/readiness diagnostics; `geometry-valid` does not imply pressure-ready, services-ready, spawn-authorized or complete Wayfarer. Do not invent certified cargo or material ratings.

## Private schema and identity defaults

Names below are proposed table/field contracts, not existing APIs. Use server-created UUIDs for all live rows; template-local IDs are immutable within their source revision and are never reused as global instance IDs.

- `construction_grant(id, principal, scopeKind, scopeId, capability, revision, expiresMicros?, revokedMicros?, issuedBy)`. Capabilities: `draft.read`, `draft.write`, `blueprint.publish`, `instance.spawn`, `instance.refit`, `instance.capture`, `grant.manage`. Scope is one document/template/frame or explicit development workspace. No self-grant reducer. Seed named development-review grants through a reviewed operator migration; no wildcard grant for every login. Expiry/revocation is checked on consumption and projection.
- `blueprint_document(id, workspaceId, owner, revision, schemaVersion, canonicalJson, sourceLiveId?, sourceLiveRevision?, updatedMicros)`. Mutable draft, bounded at existing1MiB maximum; exact server canonicalization. Local checkpoint bytes/history remain separate, available for explicit adoption/export.
- `blueprint_revision(id, documentId, revision, canonicalJson, compilerVersion, adapterManifestDigest, canonicalDigest, validationSummary, publishedBy, publishedMicros)`. Immutable publication; unique `(documentId, revision)` index. Published native dependency hashes must resolve through approved catalog records, never arbitrary client URLs.
- `construction_instance(shipId, blueprintRevisionId, layoutRevision, compilerVersion, compiledDigest, migrationKind)`. Absent row means the existing legacy fixture; never infer the presence of a construction instance from its ship name or asset.
- `instance_deck(id, shipId, sourceDeckId, elevationUnits, floorThicknessUnits, clearHeightUnits, ceilingThicknessUnits, supportData, boundaryData)`. Unique source-deck mapping within a ship. Structural surfaces and occupied volume must fit the approved adapter metadata; all dimensions are lattice integers until deterministic metre conversion.
- `instance_object(id, shipId, deckId, sourceObjectId, definitionId, definitionRevision, localPlacement, stateDomain)`. Unique instance/source mapping; actual inventory, door, actuator, reservoir or station row retains its own stable ID and is bound explicitly. Immutable visuals may be shared; state cannot.
- `character_deck(characterId, shipId, deckId, revision)`. Additive companion to the existing character row initially. For authored ships it is mandatory; on legacy ships absence selects the explicitly named legacy deck adapter. Movement never trusts an input deck ID.
- `traversal(characterId, transitionId, phase, startedMicros, sourceDeckId, destinationDeckId, revision)` and `transition_reservation(id, transitionId, characterId, expiresMicros)`. Introduce with traversal gameplay, not as a fake editor teleport.
- `construction_receipt(id, principal, operationId, requestCanonical, resultCanonical, resultRevision, createdMicros)` plus append-only `construction_audit`/tombstones. Bound retry records; prune only with retained revision protection or a compact permanent creation ledger. A pruned spawn receipt must never mint the same operation twice: spawn takes a revisioned workspace/issuance record, not an unversioned `spawn()` call.

New principal-owned construction rows also extend the identity-migration boundary. `auth.acceptIdentityLink` currently transfers character/ship/edit-receipt ownership only. Before enabling construction ownership, either implement an audited transfer of owned documents and explicitly reviewed document grants, or reject linking when unsupported construction ownership exists. Never orphan drafts under a retired identity or silently copy administrative/workspace privileges. Existing immutable authorship/audit identities remain historical.

Do not destructively add mandatory deck columns to all existing tables. Companion rows and nullable/defaulted additive fields allow validation before migration. A published schema plan must state its indexes, bounds and exact old/new fixtures; normal publication uses `--delete-data=never`.

## Authentication and authoring grants

Retain current game admission checks. A provider login, possession of a blueprint UUID, ship ownership, named-room access label, docking or camera selection grants no construction capability. Recheck explicit scope grants in each reducer and before committing any deferred/bounded job. Only intentional creator grants make a new draft writable.

The dashboard transport must be resolved explicitly before enabling its live buttons. The current dashboard-only audience is intentionally denied by the game database, and `ViewCtx` cannot distinguish sockets of the same principal. Do not remove that guard to make the editor connect. Recommended resource model: obtain a separately authorized game/world-resource token for an explicitly granted author, while retaining the distinct dashboard public client and its normal dashboard login. The provider mapper/consent and exact redirect require integration-owner review; a dashboard-only token remains insufficient. Alternatively a deliberately designed authoring API facade may validate dashboard credentials and delegate narrowly, but it must not turn a service credential into unrestricted client-selected identity or state writes. This plan does not silently choose or implement such a facade.

Until that transport decision is approved, prove reducers with explicitly granted real game-resource review identities in the isolated database and keep unsupported dashboard publication disabled. Never use module-owner credentials in browser code. Views expose authorized draft summaries/documents/instance construction data with explicit columns; no private base tables alongside them. Interior discovery for visitors remains a separate policy, not an editor grant side effect.

## Proposed reducer contracts

Every modifying action carries an operation UUID and relevant expected revisions. Validate bounded serialized size before compile, then permissions, pinned dependencies, geometry/collision/service requirements and resource/custody effects before writing. Any error rolls back the entire transaction.

- `createConstructionDraft(name, kind, expectedWorkspaceRevision, operationId)` creates a server document UUID and explicit creator grant; never overwrites an imported local draft.
- `saveConstructionDraft(documentId, expectedRevision, canonicalIntentJson, operationId)` saves design intent only. Client diagnostics/fingerprints are advisory; server recomputes them.
- `publishConstructionBlueprint(documentId, expectedDraftRevision, expectedCatalogRevision, operationId)` creates an immutable revision, with a capability/readiness result. It does not change instances.
- `spawnConstructionInstance(blueprintRevisionId, spawnAnchorId, expectedSpawnLedgerRevision, operationId)` validates a server-known spawn zone, occupancy and explicit grant. No arbitrary world transform, velocity or resource balance arguments. Initial authoring review may use one approved isolated spawn anchor.
- `applyConstructionRefit(shipId, expectedLayoutRevision, expectedStateRevision, publishedRevisionId, retainedMappingJson, dispositionPlanJson, operationId)` is disabled until live-state conversion/disposition is implemented. Client mappings are proposals validated against actual UUIDs and current contents/occupancy.
- `captureConstructionDraft(shipId, expectedLayoutRevision, expectedStateRevision, expectedWorkspaceRevision, operationId)` produces a new reviewed draft, not a publication. Capture excludes live cargo, gas, fuel, stored energy, crew membership and copied owner/control grants by default. Explicit loadout templates refer to approved new-resource definitions, never copied player balances.

Spawn and save retries return the original result UUID. Concurrent expected revisions conflict. Undo of a committed edit submits a new validated inverse against current revisions. A later blueprint revision never updates existing instances implicitly.

## Deterministic topology and collision

Keep integer1/32m planar vertices and canonical orientation. Split partially shared collinear edges before cancellation; reject zero-area, overlap, unmatched/non-manifold edges, unsupported intersections and undeclared holes. Reject detached structural islands unless a rated connector explicitly joins them. Preserve declared source IDs; derived edge IDs use deck + canonical endpoint/source descriptors, not insertion order or the current cache hash alone.

First slice retains the compiler's current partition-on-shared-edge restriction. Arbitrary partitions inside one tile require an explicit planar subdivision implementation and tests; do not approximate such a partition by assigning an entire tile to one room. Roof and floor polygons must share structural boundaries and validate openings/penetrations, including triangles and trapezoids.

Collision has separate representations: floor support polygons; finite-thickness opaque/solid boundaries; door/jamb/opening sweeps; equipment occupancy/clearance; and exterior ship collision. Radius-offset crew boundaries must account for standing clearance where the native canopy slopes inward. Use the approved adapter section, not GLB AABB as a replacement authority shape. At runtime, sweep the crew circle/capsule against its current deck's segments and obstacles, preserving sliding and no-tunnelling behavior. Server reach uses the same deck/door/LOS topology; another deck at identicalXY is not nearby.

For authored instances, remove `constrainLabDeck`, `CABIN_COLLIDERS`, `CABIN_PARTITIONS`, fixed storage coordinates and laboratory actuator constants from their dispatch path. Keep those functions only behind an explicit legacy adapter until conversion. Derive renderer deck base from the same instance-deck walking surface; cutaway/roof visibility does not change collision, sealing, lighting ownership or gameplay.

Exterior mass/inertia/collision must be compiled from approved physical definitions independently of visual armor bounds. Do not reuse the current fixed capsule or invent mass from mesh triangles for arbitrary authored ships. An initial conservative derived hull proxy is acceptable only with bounded overreach and tested swept contacts/torque about the canonical centre of mass; unsupported geometry rejects playable flight.

## Downstream interfaces and completion slices

**Playable decks.** Transition definitions have source/destination deck anchors, approach clearance, allowed body size, duration/capacity and interruption policy. Begin with one real stair/ladder adapter and deterministic server traversal; reject use while occupying a helm/couch or if either endpoint is blocked. Walking input cannot pick a destination frame. Reserve the destination, clear stale movement, advance bounded phases and commit deck/localXY only at validated completion. On disconnect/interruption restore a specified safe endpoint without crossing a sealed door. Lifts add power/door state later. Renderer interpolation follows traversal, not camera tabs. Add authoritative frame transfer before claiming airlock egress/reentry.

**Pressure.** Compile immutable volume cells and boundary/portal provenance independently of room labels. Runtime compartment IDs derive from connected sealed-volume cells; opening a door changes flow edges and effective seals, not source room ownership. Store gas in conserved units (recommended moles, fixed293.15K first solver, pressure via `nRT/V`); use bounded nonnegative conservative flow with vacuum as explicit exterior. Splits/merges remap gas by overlap/volume once and conserve total moles. Door-state revision invalidates topology consistently with walking/LOS. Armor damage does not breach an intact pressure boundary. Airlock controller owns two real pressure doors/chamber/pump/interlock and checks differential pressure, power, obstruction and emergency intent; an animation alone is not functional cycling.

**Cargo.** Introduce ship/deck-rooted cargo grids and container custody. Preserve each item/container UUID; eliminate the assumption that all accessible world storage is indexed by the viewing character. Add an explicit root binding that distinguishes carried inventory, installed ship storage and cargo-grid placement while retaining legacy rows until conversion. Physical3D container occupancy is separate from internal Tetris cells and liquid litres. Authored bearing patches/tier heights/load limits—not visual AABBs—govern support. Validate union contact coverage, uniform height, dependency DAG, load distribution, restraints and handling/door/ceiling clearance atomically. Four1×1 tops supporting a2×2 container must succeed only when their union and ratings permit it. Moving a lower support cannot leave orphaned upper containers or delete contents. Unsupported existing73 cargo visual variants remain catalog-only until interfaces are supplied; no runtime scaling.

**Services.** Extend route nodes/paths to explicitXYZ and deck/compartment boundaries. Crossings do not connect; endpoints/ports/junction IDs do. Typed medium/capacity/direction and sealed penetrations are mandatory. Compile bounded network components, then evaluate deterministic allocation and actual conserved reserves. Installed functional rows reference ports rather than room labels; lost power/fuel disables achieved actuator capability, without direct velocity damping. Pumps, lights, doors and ventilation read authoritative supply status. Store dirty topology revisions so simulation does not recompute every route every tick. Keep thermal and data policy limits explicit.

**Instances and ownership.** Two spawns allocate disjoint ship/deck/fitting/container/item/door/service/control state IDs and may share only immutable source/visual data. An owner with multiple ships is not implicitly aboard or piloting all of them. Client gameplay selects `actor.shipId`, not the first owned ship row. Multiple control stations require a new per-instance indexed station domain or a staged removal of the legacy unique-ship constraint; never create hidden duplicate helm grants. Shared-space player discovery/rendering and inter-ship interaction need their own permission-backed projections; independent private fixtures do not establish those features.

## Migration and acceptance order

1. Preserve and classify every current native placement; record unresolved nominal/functional interfaces and source hashes. Introduce new private tables and legacy-dispatch fallback without migrating existing gameplay automatically. Run additive schema publication rehearsal on a copied/isolated database, then normal publication only when coordinated.
2. Implement grant/CAS/receipt/private-view rules and server publication using the current bounded compiler. Prove wrong account, revoked/expired grants, stale writes, reordered-but-equivalent canonical input, operation collision and duplicate creation after receipt pruning. The1MiB/2048-tile caps are admission maxima, not measured safe per-tick budgets; benchmark compiler cost before accepting worst-case live requests. If necessary stage a bounded server-owned compilation job with final permission/revision recheck, never client-trusted compiled output.
3. Instantiate two isolated authored frames with different native floor polygons. Prove source-ID mappings, disjoint state, matching support/collision, doorway passage/perimeter blocking, item isolation, no owner-only pilot grant and real reload/restart persistence. Wire the real dashboard publication/selection path after authoring authentication is approved. Save actual game and Shipyard evidence.
4. Add playable transitions, pressure/airlock/egress, cargo supports and3D services through the interfaces above. Include conservation/split/merge, failed/interrupted traversal, door interlocks, unsupported cargo removals, incompatible or unsealed risers and disabled actuator supply. The completed Wayfarer requires these, not only step3.
5. Publish a complete reconstructed Wayfarer through the same editor/reducer route; no separate hardcoded exporter that bypasses compiler/authority. Spawn two and mutate one to prove independent cargo, doors, atmosphere, services and damage. Capture is separately reviewed and excludes copied live resources.
6. Only on explicit existing-ship conversion: compute a preview migration mapping retaining current ship/crew/fitting/container/item IDs, verify both layout and aggregate-state revisions, resolve every displaced fitting/occupant/container, and commit atomic mappings/derived state/audit. Preserve the original four storage binding/container IDs and current R006 station identity; reject unresolved disposition. No automatic starter kit, relocation, empty-container replacement or deletion. Recovery is a validated inverse plan or operator backup restoration with its own coordinated lifecycle, not a silent rollback over later player work.

Run focused pure/authority tests, isolated real multi-account smoke, actual browser interaction review, full checks/build and art validation. Keep native asset revisions and live migrations separately recorded. Shipyard labels, diagrams, disabled placeholder controls and an approved visual model never count as implemented pressure, services, armor ratings or multi-deck gameplay.
