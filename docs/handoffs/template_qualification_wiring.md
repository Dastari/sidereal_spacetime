# Additive template qualification: narrow integration contract

Implemented, unregistered: `packages/sim/src/template-qualification.ts`. Five focused tests exercise actual362f canonical compilation with deliberately synthetic test admission certificates and a second metadata-only test revision. They do not qualify new wall art or manufacture gameplay approval. No shared callers/catalog/entrypoints changed; there is no exported default registry and no wall candidate record.

## API and trust boundary

`createTemplateQualificationResolver(trustedRecords, explicitRefitEdges)` compiles each registered canonical document, verifies its independently pinned qualification-manifest hash, checks capability hashes/deck/object IDs, and retains frozen copies. Registration inputs come only from reviewed server content/build configuration. Never accept them from reducer arguments, client drafts, transport rows or a dynamically calculated “latest” artifact.

- `resolveSource({sha256,canonical})` reconstructs/compiles the exact source on install, refit or cached-source invalidation. A copied hash over changed JSON fails. For an instance, first reverse its private saved UUID map and restore its source ID/layout source fields using the existing reconstruction discipline.
- `resolveBinding(sourceSha256, capability, actualPins)` compares the certificate's source SHA, definition ID, definition SHA, geometry SHA, source deck and source object list. Each capability must explicitly bind the same source SHA as its admitted manifest; reusing a definition hash cannot rebind old geometry evidence. Supply pins from the installed authoritative binding and build-verified adapter definition. It does not accept “same faction”, nearest revision or old-proof fallback. Keep this bounded lookup in tick paths; do not compile whole instance documents every frame.
- `resolveRefit(fromSnapshot,toSnapshot,qualificationSha256)` requires both exact source admissions and a separately admitted **directed** transition. Each edge also pins the from/to qualification-manifest hashes, so changed bindings cannot inherit an old transition certificate. Two individually admitted templates do not authorize conversion in either direction. This remains eligibility only: expected revision, operation receipt, ownership, current occupants/support and preserved state are still mandatory.

The manifest hash binds source SHA plus all capability pins. Its expected hash must be independently fixed in the reviewed content/build record; calculating a new expected hash from an untrusted submitted manifest would defeat the boundary. Definition hashes are not permissions. Existing private session/admission/ownership/control/station/lease tests remain unchanged.

## Shared wiring checklist

1. Add the sim package export only when parent owns its integration window. Create a trusted immutable registry with362f **first and retained**. Leave the wall candidate out until geometry/batching/source certificates pass. Keep onboarding's chosen template separate from the set of supported existing templates.
2. `sim/wayfarer-walking-bindings.ts`: select a registered proof adapter by exact source/geometry hash. Preserve private instance-map reconstruction, cardinality/source checks, body envelope and threshold behavior. Restore original layout IDs/source metadata from the selected trusted source record, not a new global hard-coded ID. Each adapter still validates its own native proof; the registry does not create colliders.
3. `sim/wayfarer-starter.ts`, `world/wayfarer-starter.ts` and `world/wayfarer-starter-authority.ts`: fresh creation may select one explicitly configured admitted revision. Existing entitlement receipts resolve their recorded source; never require them to equal whichever template is newest.
4. `sim/game-ship-access.ts` and `world/game-ship-access-authority.ts`: retain all current auth/actor/admission/location/private-binding comparisons. Source eligibility must require the admitted walking capability, not only registry membership. The existing`instance.revision===1n` rule cannot simply disappear: a validated refit must atomically write the new instance revision and matching private certified binding; access still demands equality and exact source reconstruction.
5. `world/scoped-inventory-installation.ts`, `sim/construction-functional-instances.ts`, `world/construction-interactions.ts`: replace only source-specific adapter selection. Preserve all revision/definition/UUID checks, collision/LOS/reach, unique seating and grant/disconnect recovery. Cache keys include source SHA, document and UUID-map identity; new source cannot hit an old geometry cache.
6. `sim/construction-flight.ts` and `world/construction-flight-resolver.ts`: select the exact admitted source/definition pair, retain current instance revision and all10fitting checks. Translate lookup rejection into the existing per-ship invalid/inert result; do not let an unknown binding throw through the global world tick. The tick must not silently fall back to legacy flight or newest definitions for an unknown authored ship.
7. `sim/wayfarer-refit*.ts`, `world/wayfarer-refit*.ts`: keep the existing legacy conversion supported. Add a distinct expected-revision50-ID refit adapter with the directed certificate, preserve extra fuel/item/container/fitting/actor state, and atomically rebind walking/cargo/seat/pilot/private game access. Do not reuse the old conversion's reseeding path on an already-native ship.

Required combined proof after wiring: old362f spawn/reconnect/cargo/seat/pilot remains valid after a new revision is added; unknown source/pin mixing fails; an occupied/unsupported/stale refit fails without partial changes; an explicitly admitted old→new refit preserves all UUID/state; unapproved reverse/refit edges remain rejected. Current helper tests cover admission mechanics only, not this future integrated authority journey.

Batching coordination: the parallel agent is preserving all48native source GLBs and50placed frames, batching only within each placement. Its preliminary570→181group result does not change native source hashes. Pin its eventual surface/material equivalence and helper validation separately; it must not be substituted for new collision, support or refit certificates.
