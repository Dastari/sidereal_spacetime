# Persistent atmosphere adapter — staged

2026-09-09. Parent integration owner implemented this after a new specialist spawn was rejected by the thread limit. Files: `packages/world/src/construction-atmosphere.ts`, `construction-atmosphere-tables.ts` and focused tests. These are not registered in the world schema or called by gameplay yet. The published roof checkpoint remains separate.

`initializeAtmosphere` accepts a server-owned instance and a trusted accepted pressure structure. Default allocation is vacuum. A nonzero initial charge requires an explicit allocation identity and complete compartment gas rows supplied by a separately authorized template/resource transaction. The helper does not authorize or mint that resource allocation. Repeating the same initialization returns the persisted row; conflicting owner/model/allocation is rejected. It must not be used to refill a ship on reconnect.

Private `construction_atmosphere` stores immutable-model JSON, native-validation hash, initial-allocation hash, current gas JSON, source/vented/removed mole accounting, revision and last consumed simulation tick. One row belongs to one instance. The helper projects owner-only compartment pressure/volume/deck information without exposing its base table or native-validation document. The parent must wrap this projection in the existing game admission/view guard.

`stepAtmosphere` runs the existing fixed-temperature finite-flow solver for one explicit fixed simulation interval. Duplicate/older tick numbers are ignored. It is not wall-clock/offline catch-up. Gas exchange remains finite even with an open door; no instantaneous compartment merge is introduced. The admitted prototype budget is 32 atmosphere instances, 256 cells, 256 active flow boundaries and 2,048 declared boundaries per instance, with 262,144 serialized model bytes. These are work limits, not a measured server-capacity claim. The trusted model adapter must supply actual closed/open/seal conductance rules; this helper cannot make the known unsealed native kits airtight.

`replaceAtmosphereModel` checks expected revision and conservatively remaps gas by stable cell IDs. Charged removed cells reject by default. Explicit venting updates the vent ledger. Explicit capture returns a mole receipt and updates the removed ledger; the parent must commit a receiving resource in the same transaction or reject the change. This helper does not create a reservoir or authorize refit/damage. The parent also owns operation receipts and actor/proximity permissions.

Five focused tests cover initialization/tick replay, vacuum defaults, finite exchange, vent conservation, serialized rehydration, independent instances and private projections, model compression/removal accounting, and admission/numerical/clock/disposition rejection before row mutation. These are adapter tests, not SpacetimeDB process-restart or live pressure gameplay proof. TypeScript checking passes.

Required integration: an actual trusted native coverage/free-volume factory feeding `buildLayoutPressure`; explicit structural/seal/flow definitions; exact physical gasket/threshold and complete wall/floor/roof contacts; schema registration, spawn/tick/model-edit wiring and generated views; initial gas/resource policy; actual UI pressure/airlock controls and isolated real reducer/browser tests. No client-provided `validated: true` payload is acceptable. Native damage and deck traversal must update geometry and gas through the same validated transaction path.
