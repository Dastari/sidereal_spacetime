## Executable registration candidate — 2026-09-10

`packages/world/src/construction-airlock.ts` now implements a private, instance-keyed controller and a minimum keyed own-occupant projection. It is **not registered or deployed** yet. Its new tests use actual native geometry, the real construction permission/operation ledger, the real gas store/solver, and explicit host boundaries for admission/input-control.

The existing native assets have no qualified independent service-handle socket. This capability is therefore labelled **manual service operation**, not a motor, pump, powered door or invented visible crank. An accepted command binds one actor, connection/control lease and one door for at most three seconds. Each fixed step rechecks game admission, connection, input control, both workspace grants, accepted instance/deck, ordinary standing state, supported native position and clear nearby approach. It drives only that selected mechanism. Loss stops at the accepted hinge/gasket pose without moving the actor; reconnect never resumes an old operation. A fresh nearby validated command is required. Opening remains subject to actual differential pressure, the other door's fully deployed seal and native swept-body obstruction. Disconnected bodies still obstruct a moving leaf.

The new gas store starts at vacuum and installation replay preserves its contents/accounting. There is no refill or pump endpoint. Door closure, gas equilibrium and expired service become inactive, eliminating idle writes. The shared patch also scopes the older single-room gas solver to its admitted instances; two controllers must never step the same atmosphere row. Only actual changed hinge/gasket/gas/driver state advances the new controller clock.

Run `python3 scripts/stage_airlock_integration.py`, then `npx tsx scripts/validate_airlock_patch.ts` and `npx tsx scripts/validate_airlock_spawn_patch.ts`. The generator records exact before/after hashes in `native_external_airlock_patch_inputs.json`, stages `native_external_airlock_integration.patch`, and never edits shared source. The compiler host reads the proposal in memory. The executable spawn gate bundles the same overrides and proves two fresh instances, 182 independent mapped identities, 140 native parts, four door identities, 32 floor identities, reload stability, closed barriers and both separately opened continuous native routes.
