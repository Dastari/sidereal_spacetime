# External airlock staged shared integration

2026-09-10: implementation contract only; none of these shared mutations are applied during the current release freeze. New pure/document/renderer files are executable and tested separately. Main proof and limitations: `native_external_airlock.md`.

1. `packages/content/src/construction.ts`: move the exact `NativeAirlockBinding` interface from the new sim document module into content; add optional `airlockRoom?: NativeAirlockBinding`. This binding includes exact pin, deck, two opening IDs, exhaustive 70-part source index mapping, 12 roof tile IDs and four exterior tile IDs. The shared model must never accept a bare `airtight` boolean.
2. `packages/sim/package.json`: export `./construction-airlock-plan`, `./construction-airlock-controller`, `./construction-airlock-document`. Keep the controller/plan independent of world registration. Publish the exact audit bytes through a new content module/export using SHA `eb7eab8523d68906a302a84cf06a5b2a507229d15e89fb96f66d1ade8b6e0aa6`. Source file validation occurs at build/install; a world runtime factory accepts only the exact pinned audit bytes without loading native GLBs into the world bundle.
3. `construction-transactions.ts`: add `airlockRoom` to allowed top-level keys and call the new exact validator. The current `readNativeAirlockDocument` delegates base validation to `readConstructionDraft` **after removing `airlockRoom`**, so maintain that direction to avoid recursive parser loops. Validate before UUID allocation or writes. Sort mappings deterministically after validation. Do not enable pressure readiness merely because a draft has a binding; the installed two-door authority must be registered in the same release.
4. `construction-instances-model.ts` and spawn identity remapping: enumerate/remap every identity from `nativeAirlockDocumentIdentities`, including native part IDs and both opening IDs. The two-instance remap tests supply the exact coverage list. Native sources are immutable shared data; placement IDs, chamber cells, door actuator state and gas stores are per instance. Compare actual server-owned placement lists with the compiled native installation before installing gas/door state.
5. Native floors/roof/boundaries: the exact fixture adapter owns all native placements. Use its 12 roof tile IDs to omit exterior roofs and prevent generic structure from being rendered or certified over the platform. The generic floor support footprint includes all 16 native tiles. Keep the boundary/door collider source separate from visuals. Do not use the generic semantic orientation for the outer door: its accepted frame is `(6,2)`, quarter-turn **3**, while its semantic opening spans X=6,Y=0.375..1.625. The inner door is `(2,0)`, quarter-turn **1**. That distinction determines hinge sweep and physical gasket support.
6. `construction-doors.ts`: install/bind both exact door frames and leaf colliders, with ordinary scoped proximity/revision/operation checks. All target changes for these bound doors must route through the airlock controller before either leaf moves; the existing unbound single-door reducer remains unchanged. Native seal/hinge state is per opening, not one `doorId` on the old single-door pressure row.
7. NEW world airlock adapter/table: private instance-keyed immutable binding plus accepted controller state, proof/install hash, two actual door IDs, and two gas cell IDs. Reuse the atmosphere store and bounded clock; default vacuum. Only active door/controller/gas changes write. Supply current power/grant/input/pressure/obstruction on consumption. Pending unsupported egress does not delete support or create access. An exterior platform is not a suit/docking/EVA capability. No pump gas route until real native port and conserved supply authority are qualified.
8. `packages/render/src/construction-instance.ts`: if exact airlock binding is present, load `loadNativeAirlockScene` before the generic floor/roof/wall branches. Inputs: instanceId, deckId, the exact 70 mapped installation parts, elevationM **0** for this fixed-datum fixture, exact seven source URL/hash pairs, and both accepted opening/frame bindings. Parent/world origin mapping remains unchanged; native floor top already exists in GLBs. Return that loader's placements, meshes, camera frame, walking elevation, `setDoors`, `setView`, and idempotent disposal. Do not mix in the old pressure-room loader or duplicate floor geometry.
9. `world/index.ts`, generated bindings and App/net: register keyed own chamber/pressure/door projections guarded by game admission, accepted instance/deck and read permission, plus normal target reducers. Preserve existing minimum egress/seat projections. Client controls emit intent only; renderer consumes accepted hinge/gasket state. Hidden actors/roofs and character camera mode confer no authority.

Before activation: exact native material/source checks, full check/build/art gates, fresh isolated baseline, then two fresh instances and real-provider intent/reconnect/permission/CAS/gas-conservation journeys. Actual browser review must show independent inner and outer morph/hinge motion, supported walk-through, roof/landing visibility, obstruction, pressure rejection and no public/private view leakage. No normal Wayfarer attachment/refit occurs until its own aperture and floor interface are separately qualified.
