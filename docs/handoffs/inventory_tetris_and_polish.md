# Inventory grid and character polish

2026-09-09. Implemented and active in the normal game. This supersedes the default-view and header details in [the original QoL handoff](inventory_qol.md). Current living revisions: `ui.inventory-slots` r003 and `ui.character-status-and-equipment` r005; fixed-grid r002 is preserved. Final owner artistic sign-off remains unset.

Slots is the default for each inventory. Icons remains optional browsing; it cannot bypass physical packing. Every Slots grid uses 48 logical UI units per cell, subject only to the global UI scale. Pockets, backpacks and crates retain the same item size. Wide grids scroll with arrows, the horizontal bar, trackpad or Shift-wheel; tall grids scroll vertically. Filtering dims nonmatching occupied cells in place. A held item keeps its complete oriented footprint and shows geometric fit in green/red. Its source stays visible until the server commits a move; this is a local preview, never client-authoritative placement.

Storage headers now contain Take all on the left and actual nested payload/capacity on the right, using the same bar style as personal inventory. Personal inventory shows Store all when a transferable world container is open. Store all transfers the fitting contents of the selected carried inventory into the most recently focused open world container. Equipped items stay equipped. It uses one expected revision and operation receipt, preserves item/container UUIDs and nested contents, rechecks access/reach and leaves items behind when they cannot fit. Item counts/grid dimensions, click instructions and redundant nested-storage buttons are removed. Nested storage remains accessible from item context actions. Existing Shift transfer, drag/drop, paper-doll slots and ground drops remain.

Character equipment no longer contains Body/Hair controls or the appearance footer. Its preferred height is slightly increased and the equipment content is shorter; all ten slots and rotation controls fit the default desktop view without scrolling. Small screens retain vertical scrolling. Escape → Crew retains body/hair style and adds eight named skin swatches and eight hair colors. Both use existing validated persisted color fields and authored material roles; no model, rig or equipment authority was replaced.

Equipped items with real grid containers can appear as inventory tabs, wrapping when needed. Loose nested bags use their item context action instead of redundant bottom buttons. Future belt/trouser storage needs authored definition capacity and authoritative provisioning before it is usable. Tooltip storage dimensions and payload already derive from the definition's real storage data; this pass does not invent extra armor storage.
