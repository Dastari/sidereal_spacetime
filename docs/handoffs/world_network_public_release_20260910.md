## Recovery

Prefer a forward repair preserving state. A client-only rollback is incompatible with the newly required input lease. Do not restore the database archive over a running server or roll back accumulated gameplay as an application rollback. For a pre-acceptance full recovery, coordinate downtime, validate/extract the private recovery archive into a separate path, retain the failed current data, and restore the matched server data/config plus explicitly selected previous immutable client. Full restoration remains an operator action and requires preserving post-backup changes where applicable.

## Public browser finding and corrective authority contract

The socket itself survived, but world admission disappeared after the host ticket's60-second `exp`. The module had used that shortened claim as the authenticated session expiry. The pinned SDK exchanges the original provider JWT for a re-signed host token, and the pinned2.10 host exposes the exchanged payload to socket reducers. Removing30-second reconnects exposed this existing admission coupling. Successful development-identity continuity did not validate this OIDC path.

The corrective `bind_game_session(connectionId)` reducer consumes the host-verified **original provider JWT** presented by the client through an Authorization-header HTTP call. It accepts no client-supplied identity, expiry or parsed claims. OIDC connections initially have pending admission (`game=false`); only a proof with trusted issuer/game audience, valid provider expiry and the same principal as the target live connection admits that socket. Every proof sets its exact signed expiry, including when a nearly expired provider token expires before its60-second bootstrap ticket. Repeated identical proofs are no-ops; older still-valid proofs may shorten admission conservatively.

Pinned host HTTP calls have a nonzero transient connection and run both lifecycle callbacks, so connection-ID absence cannot distinguish this transport. The host re-signer always serializes `hex_identity`; original Dastari provider tokens do not. The proof rejects any such host-token marker, while retaining host signature verification and issuer/audience validation. A custom transport carrying an original provider JWT is equally valid; the authorization property comes from the verified credential, not a claimed transport type. Normal actions consume the exact socket's stored verified expiry and recheck its immutable issuer/audience/owner; they do not re-expire admission using the handshake ticket's payload.

Primary implementation references: [host HTTP lifecycle](https://github.com/clockworklabs/SpacetimeDB/blob/v2.10.0/crates/client-api/src/routes/database.rs), [host token re-signing](https://github.com/clockworklabs/SpacetimeDB/blob/v2.10.0/crates/client-api/src/auth.rs), [serialized host identity marker](https://github.com/clockworklabs/SpacetimeDB/blob/v2.10.0/crates/auth/src/identity.rs). This contract is pinned to2.10 and requires regression review before SDK/host upgrades.
