# Laboratory pilot fixture alignment

The authored pilot bay starts beyond the habitation deck, at local Y=9, and extends to Y=13. The station is at (0,10), with the console at (0,11.25). `packages/content/src/pilot-layout.ts` owns these fixture coordinates independently of the visual asset export.

On authenticated `enterLab`, the server upgrades that caller's own known laboratory station from (0,6) to (0,10). The private `pilot_layout_receipt` table records one operation per ship, its fixture revision, preserved station UUID, previous coordinates and server timestamp. Current fixture revision is 1. An existing receipt makes re-entry idempotent. Unexpected station locations or inconsistent occupants fail before mutation; this is a narrowly scoped laboratory upgrade, not a general refit endpoint.

An occupied station keeps its occupant, operational state and identity. Its occupant moves with it. Unseated characters retain positions inside the supported deck boundary; invalid exterior positions are constrained to that boundary. All affected movement/thrust inputs and sprint flags are cleared, preserving input sequence numbers. Ship/character IDs, inventories, cargo, rename revisions and control-grant rules remain unchanged. Migration and connection update happen in the same reducer transaction. No client supplies a transform or chooses a ship for this operation.

Walking uses the generic simulation's optional boundary function with a content-defined bow footprint. Crew centres keep a 0.3 m radius away from the interior side of the 0.375 m hull, including diagonal shoulders; old room blockers remain in effect. This is the laboratory collision fixture, not automatic collision compilation from a published hull or a pressure/airlock implementation.

Validation: 16 focused simulation/migration tests pass; project typecheck passes; `npm run smoke` passes against isolated `sidereal-spacetime-dev-smoke`, including station control, walking and room collision, inventory, interactions and privacy. The corrected runtime art and authority module were subsequently deployed by the coordinating agent with `npm run world:publish` on 2026-09-08 (publication evidence: `position-publish.log`). Publication does not migrate every existing session immediately. The recorded upgrade runs on the next authenticated `enterLab` call: refresh/reconnect and re-enter the lab so that normal entry applies it. A session that remains connected without re-entering can retain its previous station coordinates until that trigger runs. Existing valid unseated crew remain at their original deck positions after entry; they can walk forward to the relocated station.

The client, renderer and dashboard initial station positions now use the shared `PILOT_LAYOUT` constant. The client interaction-distance check uses the subscribed authoritative station coordinates, so it follows the actual migrated station rather than an assumed visual position.
