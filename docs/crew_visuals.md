## Source and reproduction

Run `npm run art:crew` through the managed `scripts/dev.py` art command. [Generator](../scripts/build_crew_source.py) creates the original [editable Blender source](../assets/source/crew-frontier.blend), [runtime GLB](../assets/runtime/crew/frontier-crew.glb), [review render](../assets/runtime/crew/review.png) and [validation manifest](../assets/runtime/crew/manifest.json). Imported Blender sources and reference images are preserved. Owner references `characters-weapons-items.png`, `more-character-customization.png` and `character-animations-2.png` were examined for proportions, stepped construction, equipment separation and animation intent. No pixels, branding or meshes are copied into runtime assets.

The model has broad boots, separate knee/elbow construction, shoulder plates, face details and layered studless hair. Its 16-bone armature includes pelvis, spine, head, upper/lower arms, hands, thighs, shins and feet. All vertices have named bone weights; rigid weights intentionally keep molded construction pieces solid. Idle, Walk, Sprint and Seated are actual exported skeleton clips, each with unarmed, pistol and rifle variants (12 clips total). Walking includes hip/knee/ankle articulation, opposed arm swing, pelvis weight transfer, spine counterrotation and head motion. A visible dark knee sleeve and side hinge caps separate thigh and shin armor. Baked two-link leg targets keep stance ankles at deck height with flat soles and lift the recovery foot; idle has soft knees and seated clips lower the pelvis into a supported pose. Sprint has a shorter 18-frame cycle, deeper knee recovery, a shorter support phase, stronger arm action and forward torso lean. Weapon variants bake two-link arm solutions; the rifle uses both hands, while a pistol leaves the other arm free. There is no root-motion displacement. The editable source preserves independent parts; runtime meshes batch by selectable slot. The expanded catalog has 19 mesh groups / 62 material primitives across all hidden and visible variants; only the chosen slots render. The four-character review uses 81 visible primitives combined, including pistol/rifle fixtures.

## Renderer contract

[Renderer module](../packages/render/src/crew/index.ts) exposes `createCrewVisual(scene, parent, assetUrl?)`, returning `root`, `update`, `customize`, `sockets` and `dispose`. The caller puts `root` at its authoritative/interpolated ship-local position and heading. Feet rest at Y=0; forward is local -Z. Update accepts `moving`, `seated`, optional `sprinting`, `speed` playback ratio, `weaponPose` (`none` / `one-handed` / `rifle`) and `reducedMotion`. The caller supplies authoritative sprint presentation state; held Shift does not grant speed through this API. Without an explicit weaponPose, appearance.weapon chooses the matching held pose. Pose switches use eased normalized crossfades, including interrupted changes: 180 milliseconds between gaits, 240 milliseconds for equipping/unequipping a weapon pose, and 280 milliseconds entering/leaving the seat. Moving weapon changes and walk/sprint transitions retain stride phase so a support foot does not reset to the start of the cycle. Reduced motion freezes the selected pose immediately. Rendering never writes back position or control grants.

`customize` accepts suit/accent/skin/hair hex colors, four outfit presets, bodyStyle (`jacket` / `flight-suit`), armor (`none` / `utility` / `heavy` / `expedition`), helmet (`none` / `open` / `closed` / `engineer` / `marine` / `explorer`), hairStyle (`swept` / `cropped` / `crest`), backpack visibility and backpackStyle (`utility` / `oxygen` / `field`), and weapon (`none` / `pistol` / `rifle`). Presets choose actual distinct geometry, not only colors. A new outfit resets slot defaults and preserves skin/hair color; fields supplied in the same call override those defaults. Palette roles are independent PBR materials. Attachments remain weighted to their parent bones. This is a local appearance preview: it grants no inventory items, armor, life support, equipment permissions or persisted appearance. These require permission-checked server equipment state in a later milestone. Instances load their own materials; disposal owns their asset container and animation observer, retaining the caller's ship node.

Blender review checks silhouette. An isolated Chromium software-WebGL2 review also verified changing thigh quaternions over 300 milliseconds with root position unchanged, 11 visible default material primitives, closed-helmet colors and the seated pose. [Walking browser capture](../assets/runtime/crew/browser-walk.png) and [seated browser capture](../assets/runtime/crew/browser-seated.png) are review evidence. Browser gameplay review is part of the enclosing client integration.

This is one reusable rig with four original outfit families and mixable slots, not a production MMO gear library. Pistol/rifle objects are small nonfunctional pose fixtures for the independent equipment asset pack. No firing, damage, inventory entitlement, combat/emote suite, retargeting service, facial animation, runtime foot IK, crowds/LOD or server animation replication is claimed. The rig is GPU-skinned geometry, not destructible voxel occupancy; the construction-brick visual style does not imply authoritative per-cell character damage.

## 2026-09-08 modular sprint and holding extension

The [variant generator](../scripts/build_crew_variants.py) adds utility pouches and work brim/headlamp, heavy cuirass/pauldrons/respirator, expedition padded vest/wide visor, slim flight suit, cropped/crest hair and oxygen/field packs. The [browser lineup](../assets/runtime/crew/browser-outfits.png) shows the four families with sprint, pistol and rifle poses. Held meshes stay bone-driven; no prop changes simulation.

`sockets.handR`, `handL`, `back` and `hip` are TransformNodes parented to the appropriate linked bone nodes. Parent an external visual to a socket at local position zero. The hand grip uses local -Z forward / +Y up; the palm origin is 0.055m along the finger bone, with a roughly 0.07m wide grip and 0.13m handle height. Hand orientation is stabilized in the baked holding clips. Set `weaponFixture:false` to hide the small built-in weapon while retaining its matching pose for an external asset. Sockets and attached children dispose with the crew; these are rendering attachment points, not authoritative equipment slots.

Four GLB tests now cover modular exclusivity, hidden fixtures, external socket lifecycle/orientation, distinct sprint and rifle bone poses, crossfade, material control and preserved actor placement. Chromium WebGL2 review confirmed rifle socket up.y=0.9999 and the expected diagonal forward direction. Runtime art was regenerated through `art:crew` and copied into the client public assets with `scripts/prepare_app.py client`.


## Articulated knee and transition revision

On 2026-09-08 the rig was inspected against `character-animations-2.png` and `ui-elements-5.png`. The original shin bones existed; the visual lacked an exposed joint and its independent sine rotations did not constrain supporting feet. The revised original Blender source uses `scripts/build_crew_animation.py` for contact-aware baked leg poses, preserves all 16 bone/socket names and hand-grip frames, and regenerates all 12 clips with explicit scene-frame sampling. No animation writes authoritative movement.

Focused tests load the new canonical GLB and check supporting ankle height, lifted recovery, non-collinear knee flexion, distinct sprint motion, carbine support-palm contact, stride phase during weapon changes and normalized interrupted fades. Equipping remains a caller-supplied visual state through `CrewAppearance.weapon`; this module creates no inventory or equipment entitlement. The hand socket follows the blended skeleton. There are no authored firing/reload/draw clips or runtime floor/hand IK yet; equipment changes blend between held and unarmed poses. Full gameplay speed matching and foot placement on uneven surfaces remain separate animation work.

Real Chromium WebGL2 review used the required tailnet host on 2026-09-08, with a standalone bundled four-character scene and the canonical exported GLB. It found an additional runtime defect: a zero-delta first render stopped the newly requested zero-weight animation before its fade began. The observer now keeps the desired group alive; a regression test exercises that exact startup frame. After the fix the browser reported independently playing Idle, Walk, Sprint and Walk-Rifle groups, changing knee/ankle coordinates, fixed actor placement, and successful rifle→pistol→unarmed and sprint→seated changes. Evidence: `output/playwright/crew-knee-gaits-active.png`, `crew-equip-pistol-transition.png`, and `crew-seated-unequipped.png`. These are live animation captures, not replacement still poses. The isolated software renderer ran slowly with four detailed characters; this is visual verification, not a production performance claim. The reviewed crew assets were copied to both apps' crew asset directories only; gameplay equipment authority integration is separate.
