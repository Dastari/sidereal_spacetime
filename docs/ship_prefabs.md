## Pipeline

```
ShipPrefabDocumentV1 (grammar data)
  ├─ validateShipPrefab / prefabStats ───────────── Shipyard live feedback (content)
  ├─ dressShip ─► kit placements + generated bricks ─► Babylon prefab renderer (sim → render)
  ├─ prefabConstructionDocument ─► ConstructionDocument ─► save draft → publish → spawn (world)
  └─ prefabFlightModel ─► FlightDefinitionInput ─► compileFlightDefinition (IFCS)
```

A prefab is **only grammar data**. Every visual (cassettes, roofs, rims, slope and arc skins, floors, walls, doors, posts, object sockets) and every authority artefact (walking layout, native floor bindings, flight mass and actuators, pilot station) is derived from it deterministically. Anything a developer authors can therefore be opened, edited and republished in the Shipyard.

## Grammar (`packages/content/src/construction-grammar.v1.json`, `construction-grammar.ts`)

One rulebook, read by TypeScript and by the Python kit exporter.

- **Frame.** Prefab plan metres, +X fore, +Y port, +Z up. Heights are texels (1/16 m).
- **Cells.** 1 m. Shape tiles: `square`, `slope1`..`slope4` (1:1–1:4), convex arcs `arc1`..`arc4`, concave arcs `arc2c`..`arc4c`. Placement is a min corner plus 4 counter-clockwise quarter turns and a mirror flag (`reflected`).
- **Volumes.** A volume is a set of non-overlapping tiles plus a height class: `deck` (5–54 texels, walkable), `pod`, `cabin`, `wing`, `plate`. The tile union (edge cancellation) must be one outline, which may have holes.
- **Faces.** Tiering follows the prototype `vol_tiers`; the finite set of tier heights bounds the kit.
- **Rooms.** Rooms are labelled cell rectangles clipped to the deck outline. Corridors must be at least 2 cells wide.
- **Edges.** `wall.full`, `wall.glazed` (seals), `wall.half` (does not seal), `window`, `open`, and doors (`door.standard|sliding|airlock|blast|forcefield`). Doors span the 2 m module. Pressure compartments join through non-sealing edges.
- **Mounts.** Mounts reference SHIPS-COMPONENTS ids (`ship-components.v1`) through `ship-prefab-components.ts`:
  - `top`: footprint on a roof.
  - `face`: centred on a straight face with an outward normal. Rear means normal aft. Only XL rear mounts may overhang the face.
  - `edge`: an exterior airlock or cargo door on the walkable deck face, opening into a room.
  - `interior`: whole floor cells inside one room.
  Placement returns the component quarter turns in the game frame (rear = 0, starboard = 1, fore = 2, port = 3).
- **Blueprint size classes.** `S` 18×12 up to MD, `M` 30×18 up to LG, `L` 48×24 up to XL, `XL` 64×40. Launch rule: one deck.

## Kit (`packages/content/src/ship-kit.ts`, `scripts/art_library/ship_kit_export.py`)

`ship-kit.ts` owns the canonical piece ids and the exact prototype builder call for each. `ship-kit-pieces.v1.json` is generated by `npx tsx scripts/generate-ship-kit-pieces.ts` and pinned by a test. `npm run art:ship-kit` builds all 217 pieces headlessly from `scripts/art_library/ship_kit_prototype.py` into `assets/runtime/ship-kit/r001/*.glb` plus `manifest.json`:

- a 1-segment brick chamfer
- nine slot-named materials (`primary secondary accent trim metal dark emit_a emit_b glass`)
- hidden-face culling
- a 0.25 mm offset per overlay level against z-fighting
- byte-reproducible output

Themes (`ship-themes.ts`) are slot→material tables: Federation, Riftjack, Aurelian, Frontier Industrial, Vitreous Choir.

## Dresser (`packages/sim/src/ship-dresser.ts`)

The single TypeScript port of the prototype dresser. Every output item carries a view:

- `flight`: roofed. Hull body, both face tiers, rims, roof modules, spine and emblem, top mounts.
- `deck`: cut away. Floors, inward exterior walls, slope walls and partitions cut at 1.75 m, doors, derived posts, object sockets, room lights and labels, and a shell band capped at 2.5 m.
- `both`: face mounts, lower face tier, non-deck volumes.

It is presentation only; authority never reads it.

## Authority (`packages/sim/src/prefab-construction.ts`, `prefab-flight.ts`)

- **Construction.** `prefabConstructionDocument(prefab, catalog)` wraps a prefab into the existing `ConstructionDocument`:
  - a derived walking layout: full floor cells bound to the native `quarter-1m` / `square-2m` floor parts; partitions along shared tile edges; door openings with 0.25 m jambs; rooms
  - a `prefab` binding `{schema, revision, catalog, document}`
  `readConstructionDraft` admits the binding only if the prefab parses strictly, validates against the current component catalog revision, and the layout and floors re-derive exactly after normalisation. The unchanged `compileConstruction`, drafts, blueprints and spawn then apply.
- **Flight.** `prefabFlightModel` builds the IFCS input from grammar data and component stats:
  - one structure part per volume (area × height-class mass per m²) at its centroid
  - interior deck and wall mass
  - every component's catalog mass
  - main engines on faces as actuators (thrust along the component +Y)
  - computer cores as flight computers
  - a hull capsule and the pilot station
  This replaces the Wayfarer physical catalog for prefab ships.
