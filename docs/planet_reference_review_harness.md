# Isolated native planet reference review

This harness reviews preserved Blender-authored planet/moon candidates without changing production environment selection or simulation. Current artistic gates and limitations remain in [the iteration record](planet_reference_iteration_20260914.md); [LOD authoring requirements](planet_lod_authoring.md) still apply. An agent working visual pass is not owner final approval.

Run `npm ci`, then `npm run art:reference:check` from this checkout. The dedicated config includes the selected source parity, material/optical, NullEngine floor/visibility and worker-lifetime tests under `scripts/art_library`; the default repository test config does not collect that directory. Tests use preserved fixtures in `output/playwright/planet-reference-20260914`, including required predecessor revisions. Evidence snapshots containing historical copies of tests are archives, not additional active suites.

Browser review requires the managed client development service and an explicitly selected Playwright session. Start services only through the existing `python3 scripts/dev.py`/npm service commands. Capture tools derive the checkout root from their own path; `SIDEREAL_REFERENCE_URL` selects the managed server and `SIDEREAL_REFERENCE_SESSION` selects the browser session. A different checkout's running service/browser result is not validation of this checkout. No browser service was started during PR preparation.

`python3 scripts/art_library/stage_planet_reference.py <revision>` stages only declared runtime kit/maps/HDR into a revision-local directory. The unchanged64MiB kit cap applies. Exact Ice moon1/2 r002 projections can be staged with `--runtime-projection`: source, projected payload and equality evidence hashes are pinned and checked. The full native archives remain unchanged. Unsupported oversized kits must use a documented alternative capture path; the staging command does not silently discard variants or raise its cap.

`capture_planet_reference.py --help` describes isolated still captures; `capture_planet_reference_lod.py --help` describes the retained-LOD route. Use unique evidence prefixes. Captures record their actual source root, checkout HEAD and payload hashes. Software rendering supports geometry/count/appearance investigation, not the hardware transition frame-time acceptance criterion. Real Flight approach/retreat and Map→Observe validation remain separate from this harness.

The nine canonical family ledgers preserve exact reference crops, native sources and meaningful failed revisions, including moon checkpoints. Native `.blend` files and exported GLBs/maps are editable authoring evidence. Historical generator scripts retain their original dependencies/absolute authoring paths; this PR does not claim every historical Blender build can be replayed from an arbitrary checkout with one command. The active harness and focused test fixture closure are independently checked.
