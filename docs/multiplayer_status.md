# Networking and multiplayer status

Status: Authoritative private laboratory; shared multiplayer gameplay is not implemented.
Last verified against source: 2026-09-09

Flight, movement, helm occupancy, inventory and object interactions use SpacetimeDB reducers and private persistent rows. Clients submit intent or revision-checked operations; camera motion, selection, animation, effects and rendering are presentation. Opening a roof or hiding an interior never changes authority, collision, discovery or access.

This networking foundation is not a shared multiplayer game yet. `enterLab` creates a separate ship and celestial fixture for each identity. `ownCharacters` and `ownShips` filter by authenticated owner; `ownSpaceBodies` follows those private ship IDs. Inventory and object projections likewise restrict access to that character's lab. App composition selects one owned actor and ship and renders one crew avatar. Other accounts therefore do not currently encounter one another in a shared ship or world. Crew invitation/admission, other-player discovery projections and remote actor presentation remain pending.

Multiple browser tabs using the same identity share one character. The current `connectionPresence` and authenticated-session checks retain presence until the last usable account connection closes; the earlier one-tab-disconnect behavior is no longer the source implementation. Dedicated Dastari Keycloak login and public callback/recovery have passed browser review (see `handoffs/public_login_verification.md`). Neither that login nor isolated authority/privacy smoke establishes cross-account shared gameplay. Admission/capacity and shared-world acceptance remain distinct gates.

Closed Flight rendering now omits cabin meshes, native interior equipment, the actor and internal room/fixture lighting. Cabin spotlight textures may remain allocated, but their lights and refresh work are disabled. Deck restores the cabin before the roof opens; the closing transition retains it until the roof becomes opaque. Observe also skips cabin rendering. Hull, roof, engine effects, external navigation lighting and exterior key remain available. These are presentation/performance changes only; simulation continues unchanged. Focused tests cover view transitions, light eligibility and restoration of the authoritative per-tray light state. Actual tailnet client acceptance passed: Deck had 152 enabled cabin meshes and 27 cabin lights; closed Flight had zero of each, and returning to Deck restored both. Measured draw calls were 1195 in Deck and 568 in Flight at the respective camera positions (not a same-view FPS benchmark). Evidence: `output/playwright/cabin-deck-before.png` and `cabin-flight-closed.png`.

## Required shared-world milestone

Owner reconfirmed on 2026-09-09 that different accounts must eventually join the main multiplayer world. Current account isolation is the temporary lab design, not intended final product behavior. It is not caused by Keycloak redirect or account registration. Both accounts can use the same authoritative database while the current owner-scoped simulation fixtures and projections keep them separate.

Implement one canonical shared spatial world and server-derived discovery views that restrict both rows and columns. Preserve private inventories, permissions, inputs and hidden ship interiors. Render discovered remote ships/characters from accepted snapshots. Introduce explicit boarding/crew access with station occupancy granting piloting; ownership alone must not grant control. Existing account/character/item UUIDs and saved inventories must survive migration from private fixtures. Do not make private base tables public as a shortcut.

Acceptance requires two different real accounts in two browser sessions: both observe the same nearby world/actors, one player movement is visible to the other, approved boarding works, unapproved access and inventory reads reject, piloting rights follow station occupancy, and reconnect/restart preserves both identities and independent possessions. Until those tests pass, report the game as authoritative and persistent with private test worlds, not completed shared multiplayer. The current two-deck construction work continues; this record does not silently reprioritize the owner-approved construction sequence.
