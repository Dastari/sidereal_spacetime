# Persistent lab inventory authority

Implemented 2026-09-08. This is the bounded character-owned lab inventory slice, not full M5 sharing, refits or resource networks.

Private tables store stable item UUIDs, grid/liquid containers, character revision and starter-kit grant, five hotbar references, and at most 128 mutation receipts per character. Authenticated views expose only the current character's reachable items and containers. World containers require a connected actor on the same ship within 1.8 meters; carried/equipped descendants follow their parent item's access. Public projections omit internal character IDs, ship IDs and world-container coordinates. Hotbar references to inaccessible items are blanked. No private base table is publicly subscribed.

`claimStarterKit` grants once per character. The fixture has 4×2 pockets limited to 6 kg, an equipped 8×6 field backpack limited to 24 kg, six contents including a canister with 2 liters of fuel, and a 32 kg character carry limit. The backpack, canister and their contents retain identity when moved or equipped. A storage-room crate and engineering liquid tank are actual persistent per-lab containers, revealed only in reach. These fixtures remain isolated by the current character/lab model; shared crew/faction container grants are not claimed.

Moves, equips and hotbar edits recheck authority when consumed, validate expected revision and a bounded operation ID, and commit atomically. An equip swap stows the previous item in a valid cell/orientation in the incoming item's source grid; if it cannot fit, the whole operation rejects. Every item occupies exactly one grid or equipment slot. Pure rules reject overlaps, out-of-bounds placement, wrong storage/slot kinds, nesting cycles/depth, ancestor payload limits and excess carried mass including nested liquids. A reservoir is capacity storage, never a grid; liquid transfer and engine utility consumption are not implemented.

An exact operation retry returns without another mutation. Reusing its ID for different arguments rejects. Old receipts are pruned at 128, after which expected revision still rejects a replay. There are no client-authored inventory balances or item IDs, no delete/stack split or merge reducers (ground drop was added in the QoL follow-up below), and no implied weapon firing permission. Hotbar activation currently equips an accessible equippable item; consumable effects are not implemented.

The schema migration adds private tables and filtered views only. Existing characters claim their kit idempotently on demand. No development database reset is required. The isolated smoke verifies privacy, actor isolation, starter idempotency, nested mass, rotated packing, placement/cycle/liquid rejection, equip swaps, hotbar resolution, revision/receipt replay and actual range loss after walking away. Restart verification retains an equipped item UUID, backpack UUID and inventory revision; an actual managed restart remains a separately coordinated operation.

## Hand swap retention correction

Automatic hand swaps now prefer the incoming item's source grid only when it is carried, then search other accessible carried grids. They never silently put the displaced hand item into world storage. If no carried grid fits, the entire operation rejects with a stow-space error, preserving both item UUIDs, equipment and revision. Backpack exchanges use the separate complete-layout rule below; explicit player transfers into nearby world storage remain supported.

## Inventory QoL and persistent ground items (2026-09-09)

`transferInventoryItem`, `takeAllInventoryItems` and `dropInventoryItem` use the existing expected-revision/operation-receipt contract. Quick transfer auto-packs into the equipped backpack, then pockets; an explicitly chosen destination is authoritative only after access, fit, nesting and mass checks. Take all commits the subset that fits as one operation, preserving excess in the source. Item IDs and nested contents survive every move. The geometric search prunes occupied cells before the complete inventory validator runs.

Ground drop creates a private wrapper container/binding at the connected, standing character's server-derived ship-local position; the client supplies only the item ID. Seating blocks dropping. Existing UUIDs, backpack contents and liquid reservoirs are retained. Empty wrappers are removed after pickup or equip. The normal container budget is extended by the bounded 128-item limit to accommodate one wrapper per dropped item. Clients cannot use move/quick-transfer to insert objects into a ground wrapper; another drop creates its own authoritative location.

`ownGroundItems` exposes only the current character's discovered ground item ID, definition, ship-local position and reach flag, within 12 metres with partition visibility. Pickup still checks 1.8 metre reach at reducer consumption. No private base table or another character's ground loot is exposed. This retains the current isolated character/lab inventory model; shared crew loot and salvage choice rewards remain separate work.

The renderer loads the published item GLB into its explicit world scene and positions it from the filtered view. Holographic nameplates and Z visibility are presentation only. UI descriptions and preview prices/bonuses are deterministic presentation data, not sale values, consumable effects or combat authority. See [the QoL handoff](handoffs/inventory_qol.md) for current interaction and validation evidence.

## Store all and shared grid display (2026-09-09)

`storeAllInventoryItems` transfers the fitting contents of a selected carried container into a reachable world container, in one validated revision/operation transaction. It preserves equipped items, nested contents and UUIDs, checks contiguous grid fit and mass, rejects unavailable/ground destinations and leaves excess in the source. The client Slots/Icons view never changes these rules. Fixed-size UI cells and scrolling are presentation only. See [current UI handoff](handoffs/inventory_tetris_and_polish.md).

## Backpack pickup and complete exchanges (2026-09-10)

Implemented and validated in an isolated release candidate; normal activation is coordinated with the r009 character release. A default ground pickup equips a backpack directly when the back slot is empty, even if pockets cannot fit its rectangle. An explicitly selected inventory destination still requires full Tetris fit. When the slot is occupied, ordinary pickup retains its storage behavior; Equip/Swap is the explicit replacement action.

Backpack equip plans the entire final state before writing anything. Direct contents of the old pack move into the replacement's storage, keeping nested item/container identities and liquid state. Existing replacement contents keep their positions. The empty old pack returns to the incoming source if the complete layout is valid; otherwise the same standing/proximity/ownership-checked drop path places it at the actor's authoritative position. No intermediate free inventory rectangle is required. The old pack never contains itself, and contents are not discarded to make a replacement fit.

Contiguous rectangles, rotation, nested payload, character carry limits and depth/cycle rules remain authoritative. Packing uses bounded backtracking for transferred contents, with an explicit rearrange-and-retry error if its search budget is reached. Incompatible storage, insufficient space or excess mass reject the entire operation without changing items, containers, bindings, receipts or revision. Ground-wrapper cleanup and exact operation retry behavior also apply to exchanges. This implementation supports the current one-grid backpack storage contract; future multi-pocket equipment needs a separate explicit distribution policy.

Hologram item names are uppercase presentation. Ground backpack context menus expose Equip backpack or Swap backpack; inventory context menus expose Swap backpack when occupied. The underlying item definition names are unchanged. See [release evidence and integration instructions](handoffs/backpack_pickup_swap_r009.md).
