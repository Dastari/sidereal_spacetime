# Rendering controls and Deck performance diagnosis

Status: implemented local diagnostics and controls; 2026-09-08. Hardware FPS impact is not yet measured on the owner's machine.

F3 exposes Lighting, Equipment, Shadows, Glow, Planets and Characters switches, plus Reset visuals. Closing the window retains overrides and leaves a visible reminder. These change presentation only: they do not switch authoritative equipment power, alter inventory, remove characters or move planets. Equipment includes all 17 approved fixture placements and the four legacy cargo containers, including couch, medical bed, reactor and hydroponics. Characters includes held equipment and the selection marker. Planets retain their cached geometry while hidden. Reset respects the current Deck/Flight cutaway and authoritative grow-light state.

The actual controlled Babylon review confirmed fixture visibility 131 meshes to zero, all eight primitives of four legacy cargo containers disabled, character meshes 22 to zero, and the same three tested planet mesh IDs retained. Hull and drives remain visible. Existing off grow lights stay off after reset. The six-control window was checked at compact dimensions, including scrolling, close/reopen and reset; its refresh timer runs only while F3 is open. These paused software-renderer reviews validate behavior, not GPU throughput. Evidence includes `output/playwright/f3-world-reset-confirmed.png`, `f3-controls-compact.png`, and the matched Deck/Flight captures.

The owner's screenshots show Deck 10.69 ms/frame versus Flight 5.72 ms/frame, at the same 2744×986 resolution with all six switches off. Deck has fewer draw calls and indices, so object count alone does not explain the difference. The earlier Render CPU counter begins inside `scene.render`; it omits application work performed before that call. Subtracting it from the frame interval does not establish GPU time.

The concrete CPU problem was repeated Babylon Light receiver-list replacement, push operations and unchanged enabled-state setters in the Deck preparation path. Those operations rescan scene meshes. A regression probe measured 1,090 rescans across ten stationary Deck updates before the cache correction, and zero afterward. A separate guard avoids repeated native fixture-light setters when power/visibility is unchanged. The debug override path also keeps hidden objects disabled across unchanged frames instead of temporarily restoring and hiding them on every frame. Room transitions, disposal and actual power changes still update membership/state.

F3 now separates full application Frame CPU, pre-render Update CPU and scene Render CPU. Optional GPU frame timing uses completed hardware query samples where available, in milliseconds; unsupported timing is labeled unavailable. CPU figures are not to be added to GPU duration because execution can overlap. Lit-light and eligible-shadow-map counts honor the corresponding scene flags, while allocated maps are reported separately; eligibility does not mean every cached map redraws each frame. Transparent mesh count exposes another remaining cost category.

In a matched-camera all-off review, both views had zero camera postprocesses/custom render targets, both glow layers disabled, the same seven translucent glazing meshes, and HDR environment intensity 0.28. Thus that captured comparison did not contain an extra selection/glow pass in Deck mode. Lighting Off does not replace PBR materials with an unlit flat shader or disable environment reflections and texture sampling. SwiftShader provided no GPU timer, so this review does not attribute the owner's remaining milliseconds to fill rate or establish a recovered FPS number.
